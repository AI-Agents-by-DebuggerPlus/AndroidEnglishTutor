# Промпт для Cursor: MVP языкового тренажёра (Android, офлайн)

## Контекст
Разрабатываем базовую версию Android-приложения для изучения языков. Это MVP, работающий **полностью локально, без подключения к серверу и без сети**. Все уроки, прогресс обучения и результаты тестов хранятся только в памяти телефона.

Приложение — часть более крупного проекта (адаптивный языковой тренажёр с AI-тьютором), но на этом этапе AI-часть, backend и синхронизация **не реализуются**. Задача — фундамент, который потом можно расширять без переписывания архитектуры.

## Технологический стек
- Kotlin, Jetpack Compose
- Room (локальная БД) для уроков, прогресса, результатов тестов
- Android SpeechRecognizer (офлайн-режим, `EXTRA_PREFER_OFFLINE`) для распознавания речи
- Android TextToSpeech (системные офлайн-голоса) для озвучивания
- Без Retrofit/OkHttp и любых сетевых зависимостей в этой версии — они не нужны, пока не появится облачный провайдер

## Ключевое архитектурное требование: абстракция голосовых сервисов

Это главное условие, ради которого пишется этот промпт: **распознавание и синтез речи должны быть спрятаны за интерфейсами**, чтобы в будущем можно было подключить внешние сервисы (Google Cloud Speech, Whisper API, ElevenLabs, Azure Speech и т.д.) для повышения качества — без изменения кода экранов и бизнес-логики.

Сделай так:

1. Интерфейсы в domain-слое:
   ```kotlin
   interface SpeechRecognizerProvider {
       suspend fun recognize(languageCode: String): Result<String>
       fun isAvailable(): Boolean
   }

   interface TextToSpeechProvider {
       suspend fun speak(text: String, languageCode: String)
       fun isAvailable(): Boolean
   }
   ```

2. Реализации на этом этапе — только локальные:
   - `AndroidSpeechRecognizerProvider` — обёртка над `SpeechRecognizer`
   - `AndroidTtsProvider` — обёртка над `TextToSpeech`

3. Внедрение через DI (Hilt), с точкой расширения на будущее: провайдер выбирается через фабрику/конфиг (`VoiceProviderConfig`), сейчас всегда возвращающую локальную реализацию, но структурно готовую под добавление cloud-провайдера (например, через флаг в настройках или fallback-цепочку "облако → локально, если нет сети/ключа").

4. Не завязывай бизнес-логику уроков и UI на конкретную реализацию — только на интерфейсы, через DI.

5. Даже не начинай писать облачные провайдеры сейчас — только оставь для них место (пустые модули/пакеты `voice/providers/cloud/` с TODO и комментарием, почему они пока не реализованы).

## Взаимодействие только через кнопки Bluetooth-гарнитуры

Это ключевое требование к UX: основной цикл обучения (прослушать → повторить → следующее упражнение) управляется **исключительно медиа-кнопками Bluetooth-гарнитуры** (AVRCP: play/pause, next, previous), без касаний экрана. Экран используется только для разового онбординга (первый запуск, выбор языка) — дальше всё "eyes-free".

### Технические требования

1. **MediaSessionCompat как источник правды для команд**
   - Зарегистрировать `MediaSessionCompat` в foreground `Service` (не в Activity — чтобы кнопки работали и при выключенном экране/свёрнутом приложении)
   - Реализовать `MediaSessionCompat.Callback`: `onPlay`, `onPause`, `onSkipToNext`, `onSkipToPrevious`
   - Захватывать audio focus (`AudioManager.requestAudioFocus`) на время сессии урока, чтобы гарнитура слала события именно приложению

2. **Раскладка команд** (одиночные события AVRCP — не изобретать свой протокол двойных/тройных кликов на этом этапе, полагаться на то, что шлёт сама гарнитура):
   - **Play/Pause** — основное действие: озвучить текущую фразу урока (`TextToSpeechProvider.speak`), либо, если фраза уже озвучена — начать запись ответа (`SpeechRecognizerProvider.recognize`)
   - **Next** — перейти к следующему упражнению/фразе, пропустив текущее
   - **Previous** — повторить текущую фразу ещё раз с начала

3. **Голосовая обратная связь вместо визуальной**
   - Каждое действие подтверждается коротким TTS-сообщением ("Записываю", "Верно, следующее", "Повторим ещё раз") — пользователь не смотрит на экран, поэтому вся навигация должна быть понятна на слух
   - Результат распознавания (верно/неверно) тоже озвучивается, а не только показывается на экране

4. **Известные риски с реальными гарнитурами** (уже встречались в проекте [[androidchat-tasker]] с Pixel Buds Pro 2, учесть заранее):
   - Google Assistant может перехватывать долгое нажатие/некоторые жесты гарнитуры раньше приложения — не полагаться на long-press как на основной триггер, использовать только стандартные play/pause/next/previous
   - AVRCP-события иногда деградируют при плохом BT-соединении — предусмотреть таймаут и повторную озвучку статуса ("Не расслышал команду, скажи ещё раз" — опционально голосом как fallback позже, не в MVP)
   - Приложение должно переживать потерю и восстановление audio focus (звонок, другое медиа) без падения сессии урока

5. Экран (Compose UI) при этом не убираем полностью — он остаётся как зеркало текущего состояния для отладки и для случаев без гарнитуры, но не должен быть обязательным для прохождения урока.

## Функциональность MVP

1. **Локальное хранилище (Room)**
   - Сущности: `Lesson`, `LessonProgress`, `TestResult`
   - Уроки — статический предзагруженный контент (JSON в assets, парсится при первом запуске и кладётся в БД)
   - Прогресс и результаты тестов сохраняются локально после каждого действия пользователя

2. **Стартовый тест уровня**
   - Простой тест (multiple choice + запись произношения через SpeechRecognizerProvider) для определения уровня пользователя
   - Результат сохраняется и определяет, с какого урока начинается программа

3. **Экран урока**
   - Показ материала урока (как зеркало состояния, см. раздел про Bluetooth-управление выше)
   - Основной поток управляется кнопками гарнитуры: play/pause озвучивает фразу и запускает запись ответа, next/previous листают упражнения
   - Сравнение произнесённого текста с эталоном — простое строковое сравнение/расстояние Левенштейна для MVP, не ML-оценка произношения
   - Отметка урока как пройденного → запись в `LessonProgress`, подтверждается голосом

4. **Экран прогресса**
   - Список пройденных уроков, результаты тестов, общий процент прохождения программы

## Что явно НЕ нужно делать в этой версии
- Никакой сетевой синхронизации, backend, Telegram-бота
- Никакой интеграции с внешними TTS/STT API — только заглушки-точки расширения
- Никакой AI-оценки произношения — только базовое сравнение текста
- Никакой аутентификации/аккаунтов — один локальный пользователь

## Критерий готовности
- Приложение собирается и работает в самолётном режиме от начала до конца пользовательского пути (тест уровня → урок → прогресс)
- Замена `AndroidSpeechRecognizerProvider`/`AndroidTtsProvider` на другую реализацию интерфейса не требует изменений вне voice-модуля
- Полный цикл урока (озвучка фразы → запись ответа → переход к следующей) проходится только кнопками Bluetooth-гарнитуры, без единого касания экрана, при выключенном экране/свёрнутом приложении
- Сессия урока переживает потерю и восстановление audio focus и не завершается аварийно при разрыве BT-соединения
